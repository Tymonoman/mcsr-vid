# Screencast script — YouTube API Services compliance review, round 2

**Why a recording this time.** The written script we sent was detailed and they still came back for
more. The most likely reason is our own closing paragraph: we told them `videos.insert` has never
been run in production. A reviewer cannot sign off on a capability the tool has never performed.
This recording is the evidence.

**What they asked for, verbatim** — "a script or video recording (in English) demonstrating how the
tool uploads Minecraft gameplay videos to the creator's own YouTube channel, sets thumbnails,
retrieves video analytics, and shows the end result." Four things. Every one has a shot below.

Target length **4–7 minutes**. Screen recording with voice, in English. No editing needed; one take
is fine and reads as more honest than a cut.

---

## Before you record

1. **Pick the video to sacrifice.** The upload will be locked private permanently, because that is
   what an unaudited project does. Use **13171737** (`#9 vs #3 | Aquacorde vs Infume`) — its Short
   already has the frozen-rank mismatch and its sync was ambiguous, so of everything on the shelf
   it is the one least likely to be published.

   Do **not** try to make a shorter demo file with `npm run export:fast -- <id> --seconds=30`.
   That writes to the same `final-<id>.mp4` and would destroy the finished render.

2. **Turn uploads on.** On the lab, in `mcsr-vid.config.json`:

   ```json
   "youtubeUploadEnabled": true
   ```

   then `docker restart mcsr-dashboard`. This is the one setting the Settings tab deliberately
   refuses to change, precisely because of what it does.

3. **Confirm the thumbnail.** Open the match, thumbnail strip, press **Keep this** on the variant
   you want. Otherwise the upload has no custom thumbnail to set and shot 3 has nothing to show.

4. Have YouTube Studio open in a second tab, signed in as MCSR Replayoffs.

5. Close anything with personal information in it. The recording goes to Google.

## Shot 1 — what the tool is, and whose channel it is (~45 s)

**On screen:** the dashboard's match list, then the match page for 13171737 with the rendered video
playing.

**Say:**

> This is MCSR Replayoffs, a self-hosted tool run by the channel owner on their own machine. It
> takes a public match id from MCSR Ranked, the Minecraft speedrunning ladder, downloads the two
> competitors' own Twitch VODs of that race, synchronises them, and renders a split-timer overlay
> across both camera angles. What you are looking at is the finished video for one match.
>
> The only YouTube channel this tool can write to is the one that authorised it — MCSR Replayoffs,
> channel ID UCm2mAyONTHlmIxZzNmi388w. There is no second channel and no other user. The refresh
> token lives in a single file on this machine.

---

## Shot 2 — the upload, `videos.insert` (~90 s)

**On screen:** the YouTube panel on the match page. Show the title, the description, the tag list,
the privacy selector. Choose **Private**. Press **Upload**. Let the progress bar run.

**Say:**

> The title, description and tags were generated by the pipeline and are on disk next to the video.
> I choose a privacy status, and press Upload.
>
> The client is now doing a resumable upload: a POST to the videos endpoint with
> `part=snippet,status` carrying the title, description, tags, category 20 for Gaming, the privacy
> status, and `selfDeclaredMadeForKids` false. YouTube returns a session URL, and the file goes up
> in eight-mebibyte chunks. If a chunk fails it resumes from the Range header YouTube reports,
> rather than from a local counter.

**When the video id appears, say:**

> That is the video ID YouTube returned. Note that the video is private — and it will stay private.
> Uploads made through a project whose compliance review has not completed are locked private
> permanently. That is the restriction we are asking to have lifted, and this recording is us
> spending one finished render to demonstrate the path end to end.

---

## Shot 3 — the thumbnail, `thumbnails.set` (~45 s)

**On screen:** the dashboard reporting the thumbnail step succeeded, then the Studio tab refreshed
so the custom thumbnail is visibly on the video.

**Say:**

> Immediately after the video ID comes back, the client posts the chosen PNG to the thumbnails set
> endpoint for that video ID. Here it is on the video in Studio. If this step fails — on a channel
> that is not phone-verified, for instance — the tool reports it but does not treat the upload as
> failed. The video is up; it just keeps YouTube's automatic thumbnail.

**Then, still on the dashboard, point at the four step markers:**

> The same press also files the video into three of the channel's own playlists — the season
> playlist, one for this pair of competitors, and one per competitor — looked up with
> `playlists.list` using `mine=true`, so only the owner's own playlists are ever touched. And it
> posts the channel's own first comment under the video.

---

## Shot 4 — analytics (~75 s)

**On screen:** the YouTube panel's stats table on an already-published video, then the A/B tab.

**Say:**

> This is the read side. For the channel's own uploads the tool calls the videos endpoint with
> `part=snippet,status,statistics` and shows title, privacy, views, likes and comments — you can
> see real numbers here for videos already on the channel.
>
> This tab is thumbnail performance. It comes from a standing YouTube Reporting API job: the tool
> fetches the newest report for the job and reads the date, video ID, thumbnail impressions and
> thumbnail impressions CTR columns. This is what the channel uses to decide which thumbnail style
> to keep — you can see one style measurably outperforming the other.
>
> Everything here is the channel's own data, shown only to the channel owner, in a dashboard only
> reachable on the home network.

---

## Shot 5 — the end result (~45 s)

**On screen:** the video in YouTube Studio — title, description with the timestamps and the link to
the public match page, tags, the custom thumbnail, the playlist membership. Then the channel's
video list.

**Say:**

> This is the end result: a finished race replay on the channel, with the custom thumbnail the tool
> set, the description it generated including a link to the public match page the video was made
> from, its tags, and its place in the season playlist.
>
> Every video is built from the two competitors' own public Twitch VODs of a public ranked match,
> credited and linked in the description. Nothing is downloaded from YouTube, and no YouTube data
> is shown to anyone but the channel owner.
>
> Today this publishing step is done by hand in Studio, and that manual work is exactly what the
> quota increase removes. Thank you for reviewing.
